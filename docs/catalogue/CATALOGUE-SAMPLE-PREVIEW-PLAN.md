# Catalogue Sample Preview Plan

## 1. Feature Purpose

The catalogue sample preview feature would allow Chronicle Music Publishing to present short, controlled audio excerpts for selected works in the development catalogue.

The purpose is to support publishing credibility, licensing discussion, artist representation, and catalogue discovery without positioning Chronicle as a streaming platform or public rights marketplace.

## 2. What This Feature Is

- A future controlled preview layer for selected represented works.
- A way to help qualified visitors understand the tone, style, and licensing potential of a work.
- A supporting tool for publishing conversations and catalogue review.
- A curated presentation aid for works whose rights, representation, and preview permissions have been reviewed.

## 3. What This Feature Is Not

- Not a streaming platform.
- Not a public music marketplace.
- Not a full-song listening experience.
- Not proof that every work is fully published, registered, released, or commercially cleared.
- Not a guarantee that a work is available for licensing.
- Not a replacement for direct publishing, rights, or licensing discussion.

## 4. Rights / Truth Rules

- Only works approved for preview use should receive audio samples.
- Preview availability must not imply completed publishing registration, distribution, or licensing clearance.
- Each preview should be tied to the specific work, artist, rights context, and current catalogue status.
- Works with incomplete ownership, split, or rights information should either omit previews or display a clear review-state label.
- Any public wording must qualify licensing as "discussion where applicable."
- Preview controls should not imply download, streaming access, purchase access, or marketplace availability.

## 5. Recommended Preview Duration

Recommended duration: 30 to 60 seconds.

Default future target: 30 seconds for most works, with up to 60 seconds only where approved and useful for catalogue review.

Short previews reduce rights exposure while still giving enough context for style, quality, and potential licensing fit.

## 6. Suggested Catalogue Fields Needed Later

- Work title
- Artist / writer / performer name
- Catalogue status
- Publishing context
- Rights review status
- Preview approved: yes / no
- Preview file path or secure asset reference
- Preview duration
- Preview start time
- Preview usage note
- Licensing discussion availability
- Ownership / splits status
- Territory notes
- Explicit content note, if relevant
- Last reviewed date
- Internal rights notes

## 7. User Experience Direction

- Keep previews secondary to catalogue and rights context.
- Present audio as a controlled sample, not the primary product.
- Use restrained labels such as "Sample Preview" or "Controlled Preview."
- Keep catalogue status and publishing context near the preview.
- Avoid autoplay.
- Avoid download controls unless explicitly approved in a future rights policy.
- Keep CTAs focused on discussion, such as "Discuss This Work" or "Publishing / Licensing Discussion."
- Make unavailable previews feel intentional, such as "Preview not currently available" or "Preview pending rights review."

## 8. Risks To Avoid

- Making Chronicle appear to be a streaming service.
- Suggesting every listed work is published, registered, cleared, released, or licensable.
- Showing previews before rights and representation status is confirmed.
- Using vague labels that obscure whether a work is in preparation, under review, or available for discussion.
- Adding playback without auditability around source files and approval status.
- Creating download or sharing behavior before rights policy exists.
- Treating placeholder catalogue entries as finished works.

## 9. Future Implementation Phases

### Phase 1: Governance And Rights Readiness

- Define preview approval rules.
- Confirm who can approve a preview.
- Confirm preview duration policy.
- Define required catalogue fields.
- Decide whether previews are public, private, or gated.

### Phase 2: Content Preparation

- Identify selected works for preview consideration.
- Prepare approved preview excerpts.
- Store preview files in an approved asset location.
- Record preview status and rights notes per work.

### Phase 3: Static Prototype

- Add non-functional preview labels and unavailable states if needed.
- Validate catalogue wording and status visibility.
- Review mobile and desktop layout impact.

### Phase 4: Controlled Playback

- Add audio playback only after approval.
- Disable autoplay.
- Avoid download controls unless approved.
- Ensure each preview displays the relevant status and rights context.

### Phase 5: Operational Review

- Review preview usage, rights exposure, and enquiry quality.
- Confirm whether previews support licensing discussion without creating streaming-platform expectations.
- Adjust governance and catalogue labels as needed.
