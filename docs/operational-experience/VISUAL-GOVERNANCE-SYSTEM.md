# Visual Governance System

The Visual Governance System generalizes frontend and UX/UI governance across operational experience types.

Visual design must support the user's actual task, the maturity of the system, and the operational risk of the surface.

## Page Archetypes

Common page archetypes include:

- marketing landing page
- product overview
- operational dashboard
- detail record
- workflow step
- monitoring screen
- assistant conversation
- learning module
- production workspace
- admin control surface

Each archetype should have visual rules appropriate to its purpose and risk.

## Visual Rhythm

Visual rhythm controls how users scan, pause, decide, and act.

Operational rhythm should be:

- predictable
- calm
- scannable
- consistent
- dense where useful
- spacious where comprehension matters

## Anchor Visual System

Important surfaces need visual anchors that orient the user.

Anchors may include:

- page title and state summary
- primary workflow status
- key metric group
- current task panel
- assistant guidance area
- monitoring timeline
- next action region

## Cinematic Storytelling

Cinematic storytelling can be useful for marketing, onboarding, product narrative, and selected Academy experiences.

It should not obscure operational state, reduce clarity, or make production systems feel more complete than they are.

## Dashboard Hierarchy

Dashboards require strict hierarchy.

They should prioritize:

- current state
- exceptions
- trends
- required actions
- ownership
- supporting context

Decorative visual weight must not compete with operational priority.

## Density Management

Density should match the user's task.

High-density surfaces need strong grouping, alignment, labeling, and progressive detail. Low-density surfaces need strong orientation and clear next action.

## Visual Pacing

Visual pacing determines how quickly a user can move through a surface.

Operational surfaces should pace users toward confident action, not passive browsing.

## Responsive Design

Responsive behavior must preserve usability and operational truth.

Small screens should not hide critical status, approval state, or risk. Mobile layouts should prioritize task continuity and interruption recovery.

## Asset Handling

Assets should clarify the real product, workflow, person, place, object, or state.

Asset handling should define:

- source
- quality requirements
- cropping rules
- fallback behavior
- accessibility needs
- whether an asset is decorative or operational

## Surface Locking

Approved surfaces may be locked.

Locked surfaces must not be modified unless a future task explicitly unlocks them or names them as editable.

Surface locking supports:

- review discipline
- visual consistency
- governance continuity
- protection from uncontrolled broad UI edits

## Rules by Experience Type

| Experience Type | Visual Governance Emphasis |
| --- | --- |
| Marketing Websites | Story, trust, visual interest, conversion clarity |
| Product Platforms | Workflow clarity, product identity, repeatable navigation |
| Dashboards | Hierarchy, density, alignment, exception visibility |
| AI Assistants | Conversation clarity, authority boundaries, confidence signals |
| Runtime Monitoring Screens | Truth exposure, severity, speed, calm precision |
